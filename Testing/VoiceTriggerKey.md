# 语音键触发键可配置测试（Fn / 右 Command / 右 Option / 右 Shift）

## 适用版本或分支

- 改动：语音键触发键可配置（`VoiceTriggerKey`）
- 平台：macOS 14 及以上
- 设备：RC003（RC001 如可用可一并回归）
- 虚拟设备：`MiRemoteV 2ch` 或其他已安装回环设备
- 第三方软件：豆包输入法（Fn 长按）；用户自研/第三方语音软件，其“按住说话”启动键可设为右侧 Command / Option / Shift

## 测试前准备

1. 安装并在 Remote Mic 选择一个回环音频设备作为语音输出。
2. 授予蓝牙、输入监控、辅助功能权限，并连接 RC003。
3. 打开“按键映射”页，确认遥控器示意图下方出现“语音触发键”面板：包含“用遥控器自带麦克风收音”开关（默认开）与分段选择（Fn / 右⌘ / 右⌥ / 右⇧）。
4. 打开 `~/Library/Logs/RemoteMic/runtime.log`，记录每个用例的本地开始与结束时间；关注 `VOICE FN MAPPING`、`VOICE TRIGGER`、`VOICE REMOTE_MIC`、`ATVV STREAM`。
5. 在第三方语音软件中把启动键分别配置为右 Command、右 Option、右 Shift 备用。
6. 准备一支外接麦克风（如大疆麦克风）用于“纯触发器”用例，作为语音软件的实际输入源。

## 用例 1：默认 Fn 回归（豆包 / 系统听写）

1. 保持“语音触发键”为默认 `Fn`。
2. 在豆包输入法或系统听写中，按住 RC003 语音键说话，松开结束。
   - 预期：与旧版一致，豆包/系统听写被 Fn 长按唤起并上屏；`VOICE FN MAPPING applied=true`；语音卡片徽标显示 `Fn`。
   - 预期：`STREAM_START → AUDIO → STREAM_STOP`，音频进入所选虚拟麦，尾音完整。

失败判定：默认 Fn 下豆包无法唤起、上屏异常，或音频链路与旧版行为不一致。

## 用例 2：右 Command 按住说话

1. 把“语音触发键”切到 `右⌘`。
   - 预期：日志出现 `VOICE TRIGGER key=rightCommand` 与新的 `VOICE FN MAPPING applied=true`；语音卡片徽标显示 `右⌘`。
2. 在第三方语音软件（启动键设为右 Command）中，按住 RC003 语音键说话，松开结束。
   - 预期：软件识别到“右 Command 按住”而开始收音，松开即结束；音频进入所选虚拟麦，可被该软件读取。

失败判定：软件未被右 Command 触发、松开后未结束，或音频未进入虚拟麦。

## 用例 3：右 Option / 右 Shift

1. 分别把“语音触发键”切到 `右⌥`、`右⇧`，并把第三方软件启动键改为对应键。
2. 各按住 RC003 语音键说话、松开。
   - 预期：`VOICE TRIGGER key=rightOption` / `key=rightShift`；软件分别被右 Option、右 Shift 触发；音频正常。

失败判定：任一右侧修饰键无法触发目标软件或音频异常。

## 用例 4：运行中切换触发键即时生效

1. 语音键连接可用时，在 Fn 与右⌘ 之间来回切换。
   - 预期：每次切换后立即生效，下一次按住语音键即使用新触发键；无需重启或重连。
2. 语音传输过程中切换（边界情况）。
   - 预期：当前进行中的会话按原触发键收尾，下一次会话使用新触发键；不出现修饰键卡住。

失败判定：切换后仍发送旧触发键，或切换导致修饰键卡住、语音中断。

## 用例 5：配置导入导出往返

1. 选择 `右⌥`，导出配置。
2. 恢复默认或改为其他值后，导入刚才的配置。
   - 预期：触发键恢复为 `右⌥`。
3. 用缺少 `voiceTriggerKey` 字段的旧配置导入。
   - 预期：触发键回退为 `Fn`，不报错。

失败判定：往返后触发键丢失，或旧配置导入报错/落到非 Fn 值。

## 用例 6：Typeless / Fn 点按模式下的触发键（如启用）

1. 开启“语音键模拟 Fn 点按”，触发键设为右⌘。
   - 预期：注入的点按为右 Command（开始/结束各一次配对点按）；hold/tap 状态机行为与旧版一致，只是发出的键变化。
2. 关闭该模式，回到默认按住路径。
   - 预期：恢复硬件重映射路径，触发键仍为所选值。

失败判定：点按模式下仍注入 Fn、出现多余点按，或开关切换后触发键错乱。

## 用例 7：手机 / 网页语音路径

1. 触发键设为右⌘，从附近手机或网页版开始按住说话。
   - 预期：手机语音会话开始/结束时，Mac 发送右 Command 的按下/释放；音频进入虚拟麦。

失败判定：手机语音仍发送 Fn，或按下/释放不配对。

## 用例 8：关闭“用遥控器自带麦克风收音”（纯触发器 + 外接麦）

1. 关闭“用遥控器自带麦克风收音”开关，触发键设为 `右⌘`；在语音软件里把输入源选为外接麦克风（大疆），启动键设为右 Command。
   - 预期：日志出现 `VOICE REMOTE_MIC enabled=false`；“语音键模拟 Fn 点按”开关置灰。
2. 按住 RC003 语音键说话（对着外接麦），松开。
   - 预期：日志出现 `ATVV STREAM trigger_only`，**不**出现 `ATVV STREAM accepted`；遥控器音频**不**进虚拟麦；语音软件被右 Command 触发并从外接麦持续收音，松开即停。
3. 在系统输入/音频监视里确认遥控器麦克风未写入所选虚拟设备。

失败判定：关闭后遥控器音频仍进入虚拟麦、出现 `ATVV STREAM accepted`，或右 Command 触发失败、外接麦收音异常。

## 用例 9：ON/OFF 切换与 Typeless 置灰

1. 在开/关之间来回切换该开关。
   - 预期：即时生效，无需重启/重连；开→关时日志 `VOICE REMOTE_MIC enabled=false`，关→开 `enabled=true`。
2. 关闭时查看“语音键模拟 Fn 点按”开关。
   - 预期：置灰不可点（其注入依赖遥控器音频排空）；重新开启“用遥控器麦克风收音”后恢复可用，且之前保存的 Typeless 选择恢复。
3. 在开启且正在传输遥控器语音时关闭该开关（边界）。
   - 预期：当前会话被干净结束（`isStreaming` 复位、尾音排空），不残留常驻收音或卡键。

失败判定：切换不生效、Typeless 在关闭态仍可开启、或运行中关闭导致状态残留/卡键。

## 用例 10：修饰键“卡键”回归 + 松开保证（本次修复重点）

前提：修饰键触发现在是**注入式**（屏蔽 F5 + 随 ATVV 注入按下/松开），需已授予**辅助功能**权限。

1. 触发键设为右⌘，快速连按语音键 10 次以上。
   - 预期：日志出现成对 `VOICE TRIGGER INJECT DOWN` / `VOICE TRIGGER INJECT UP`（数量配平）；**不**触发 VoiceOver、系统**不**卡顿、每次都能干净启动与停止。
   - 预期：不再出现 `VOICE FN MAPPING ... matched=1 applied=1` 把 F5 映射成 ⌘（改为 neutralized）。
2. 按住语音键不放时制造断连（关遥控器/移出范围）或直接退出 Remote Mic。
   - 预期：注入的 ⌘ 被**强制松开**（日志 `VOICE TRIGGER INJECT UP`）；系统无卡住的 ⌘（点按/输入恢复正常）。
3. 按住语音键期间把触发键从右⌘切到右⌥。
   - 预期：先用**旧键**右⌘松开，再切换；不残留右⌘按下。
4. 未授予辅助功能权限时设为右⌘并按语音键。
   - 预期：语音键惰性无害（不发 raw F5、不卡键、不触发 VoiceOver），并弹辅助功能授权提示；日志 `VOICE TRIGGER INJECT DOWN failed`。

失败判定：连按后 ⌘ 卡住 / 触发 VoiceOver / 系统卡顿；断连或退出后 ⌘ 仍按下；切换触发键后旧修饰键残留；缺权限时发出 raw F5 或卡键。

## 稳定功能回归

- 默认 Fn 下 RC003 普通语音 `STREAM_START → AUDIO → STREAM_STOP`，尾音完整，与上一正式版等价。
- 普通实体按键映射、双击/长按、Power→F20 抑制均不受影响。
- Fn 点按模式断连时完成停止手势，不遗留触发键按下状态。
- 语言切换后“语音触发键”标题、分段与状态文案正确刷新（中英文）。
- `800 × 650` 窗口下“按键映射”页各分区、语音触发面板不裁切、不改变窗口几何。

## 日志收集

1. 复制 `~/Library/Logs/RemoteMic/runtime.log`。
2. 标注用例、触发键选择、第三方软件与其启动键、开始/结束时间。
3. 重点搜索：`VOICE TRIGGER`、`VOICE FN MAPPING`、`PHONE VOICE FN`、`ATVV STREAM`。
4. 不需要提交语音内容。

## 验证边界

- 单元测试覆盖：`VoiceTriggerKey` 常量（HID usage / keyCode / flags）、mapper 按触发键重映射、默认 Fn 回归、注入键码与修饰、配置导入导出往返。仅证明进程内逻辑正确。
- 代理可验证构建、单元测试与日志，无法验证真实 IOKit 重映射效果与第三方软件识别。
- **右侧修饰键的实际识别、按住说话端到端体验、默认 Fn 豆包路径回归，必须由真实 RC003 + 目标语音软件完成真机验收；本改动尚未完成真机验收。**
- IOKit `UserKeyMapping` 将 F5 重映射为右侧修饰键 usage 与现有 F5→Fn、Power→F20 同机制，理论可行但需真机确认。
