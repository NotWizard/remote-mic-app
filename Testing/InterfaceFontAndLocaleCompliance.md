# 界面字号门槛、授权弹窗本地化与映射页遥控器插图测试

## 适用版本或分支

- 改动（Bug 编号 A9）：
  1. 设置窗口小号文字统一走 `InterfaceTextStyle` 字号 token，全部 ≥ 12pt（原 52 处为 10pt / 11pt）
  2. 附近连接（iPhone / Apple Watch）与网页版两个授权弹窗改为走 `Localizable.strings`，不再硬编码中文
  3. `RemoteMappingLayout.cardWidth` 改为保留中央通道，窄窗口下配置卡片不再盖住居中的遥控器照片
- 平台：macOS 14 及以上（Intel 变体为 macOS 13）
- 设备：RC003（或 RC001）用于稳定基线回归；一台 iPhone 与一台 Apple Watch 用于用例 4；一台手机浏览器用于用例 5
- 语言：中文与英文两种都必须走一遍，用例 4、5 的英文必须在英文界面下真实触发

## 测试前准备

1. 备份配置：`关于` → 「导出配置…」。
2. 打开 `~/Library/Logs/RemoteMic/runtime.log`。
3. 记录当前窗口尺寸。**生产窗口最小为 1020 × 772，无法手动拖到更小**——这一点决定了用例 3 的做法，见该用例说明。
4. 准备一把可测量屏幕尺寸的工具（macOS 自带`数码测色计`可放大观察，或用截图后在图像编辑器中量字高），用于用例 1 的字号确认。

## 用例 1：中文界面全部页面字号不小于 12pt（核心用例）

1. 语言设为中文，窗口保持 1020 × 772，依次点击侧边栏全部入口：按键映射、（若可见）快捷指令、统计、连接、权限、关于。
2. 每一页逐一检查以下曾经是 10pt / 11pt 的位置：
   - 连接页：iOS App / Apple Watch / 网页版三张卡片的**说明小字**、受信任设备计数标签、网页版状态文字
   - 连接页：音量增益说明、输出隐私说明、测试音状态、豆包兼容区说明与状态
   - 按键映射页：选择锁定提示、语音键模拟 Fn 提示、单击/双击/长按效果说明、快捷键录制说明、自定义应用未配置提示
   - 统计页：统计卡片**标题小字**、图表柱顶数值标签、语音排行的日期列、排行区说明
   - 关于页：版本区说明、导出/导入配置说明、Dock 图标/启动窗口/语言/重新引导四行的说明小字
   - 权限页：每条权限的说明正文
3. 预期：以上每一处中文实际渲染**不小于 12pt**；卡片标题类文字为 13pt。
4. 预期：文字变大后**没有任何一处被裁切**——不出现「…」以外的截断、不出现文字压到边框或图标上、不出现按钮被挤出容器、不出现容器高度不足导致下半行被切。

失败判定：任一中文文字目测明显小于同页 12pt 参照物；或出现上一步描述的任一种裁切/挤压；或某一行原本一行显示现在换行后被容器切掉。

> 参照物取法：`关于`页版本号旁的说明文字与按键映射页卡片标题都是本次统一后的 token，可互相比对；若某处明显更小，即为漏改。

## 用例 2：英文界面同页复查

1. 语言切换到 English，重复用例 1 的全部页面。
2. 预期：英文文案普遍更长，**页头、开关标签、按钮文字均不被裁切**；关于页语言分段控件所在行不挤压。
3. 预期：没有任何位置显示出原始 key（形如 `connection.approval.deny`、`about.preferences.language`）。

失败判定：出现原始 key；或英文标签被截断到无法辨认；或某行控件被挤出容器。

## 用例 3：按键映射页遥控器照片不被配置卡片盖住

生产窗口拖不到 1020 以下，因此本用例分两条路径，**两条都要做**：

### 3A 生产最小窗口（必须做）

1. 把窗口拖到最小（1020 × 772），进入按键映射页。
2. 预期：中间遥控器照片完整可见，两侧配置卡片与照片之间**各有明显间距**（约 32pt），照片没有被任何卡片边框或背景覆盖。
3. 预期：12 条连接线仍从卡片内缘指向照片上对应实体按键，箭头未穿过卡片，未交叉错位。
4. 预期：卡片宽度与改动前一致（本次修复在该宽度下计算结果不变，观感应当**完全没有变化**）。

失败判定：观感与上一正式版有任何差异；或照片被遮挡；或连接线锚点偏移。

### 3B 窄窗口渲染路径（必须做，用于验证修复本身）

生产窗口到不了触发宽度，只能用截图渲染工具：

```
REMOTE_MIC_SETTINGS_SCREENSHOT_DIR=/tmp/a9-shots \
REMOTE_MIC_SETTINGS_SCREENSHOT_SIZE=800x650 \
REMOTE_MIC_SETTINGS_SCREENSHOT_LANGUAGE=zh-Hans \
/path/to/RemoteMic.app/Contents/MacOS/RemoteMic
```

1. 打开 `/tmp/a9-shots/mapping-800x650.png`。
2. 预期：遥控器照片**完整可见**，两侧卡片与照片间各留约 29pt 间距。
3. 预期：卡片比 1020 下更窄（约 193pt），卡片内三个触发按钮的动作摘要允许以「…」省略，但**按钮本身不重叠、不溢出卡片**。
4. 再用 `REMOTE_MIC_SETTINGS_SCREENSHOT_LANGUAGE=en` 重复一次。

失败判定：照片任一侧被卡片覆盖；或卡片内容溢出卡片边界；或三个触发按钮相互重叠。

> 修复前该尺寸下每侧卡片盖住照片 47.5pt，可用上一正式版 App 生成同尺寸截图做对照。

### 3C 生产 minSize 字号与文案复核（2026-08-24 已执行一次）

同一渲染工具在生产 `minSize` 下也能跑，命令与 3B 相同、只把尺寸换成当前 `minSize`
（读 `RemoteMicApp.swift`，当时为 `1020x772`），中英各跑一次：

```
REMOTE_MIC_SETTINGS_SCREENSHOT_DIR=<输出目录> \
REMOTE_MIC_SETTINGS_SCREENSHOT_SIZE=1020x772 \
REMOTE_MIC_SETTINGS_SCREENSHOT_LANGUAGE=zh-Hans \
"dist/Remote Mic.app/Contents/MacOS/RemoteMic"
```

实测退出码 0，中英各出 5 张 PNG。**关键点：必须用 App bundle 里的二进制**，因为
`Package.swift` 没有声明 `resources:`，测试进程里不存在含 `.lproj` 的 bundle，
`Text("key")` 会渲染成原始键名；App bundle 自带资源表，渲染的是真实文案。

当次观察（`zh-Hans`，1020×772）：

- 按键映射页：中文全部为真实文案且清晰可读，无一处目视低于 12pt；遥控器照片完整可见、
  两侧卡片未覆盖；`单击/双击/长按` 三个触发按钮不重叠、不溢出卡片；无截断。
- 关于页：`当前版本` 为 `1.8.25-fork.4`，28pt 显示完整，未换行未截断——版本号由 6 字符
  变 13 字符后的溢出风险由此排除。
- 统计页：真实中文（`单次语音时长排行` 等）。此前测试进程截图里出现的
  `statistics.voice_ranking.title` 之类原始键名**是测试宿主 bundle 缺资源导致的假象，不是产品缺陷**。

**这一步的边界**：离屏渲染只能验证文案、字号观感、布局与截断，**不等于真实窗口验收**。
窗口几何、拖拽缩放、实时交互、系统外观切换仍必须在有 GUI 会话的真机上按用例 3A 做。

## 用例 4：iPhone 与 Apple Watch 授权弹窗本地化（英文必做）

1. 语言设为 **English**，`连接` → 「Connect Phone」进入等待。
2. 用 iPhone 发起连接，等 Mac 弹出授权弹窗。
   - 预期：标题为英文 `Allow "<设备名>" to connect to SayAll?`
   - 预期：说明为英文且提到 iPhone、2-digit code、trusted device，**不含任何中文**
   - 预期：三个按钮为 `Allow Connection` / `Deny` / `Stop Waiting`
   - 预期：中间大号校验码与 iPhone 上显示一致；用 VoiceOver 聚焦校验码时读出英文 `Verification code …`
   - 预期：弹窗宽度正常，说明文字未被截断（英文比中文长）
3. 点 `Deny`，确认连接被拒绝。
4. 重新发起，点 `Allow Connection`，确认连接建立且该设备进入受信任列表。
5. 用 **Apple Watch** 重复第 2 步。
   - 预期：说明改为提到 Apple Watch（不是 iPhone），其余同上。
6. 语言切回中文，各重复一次。
   - 预期：文案与上一正式版**逐字一致**（标题「允许“<设备名>”连接无线麦？」、按钮「允许连接」/「拒绝」/「取消等待」）。

失败判定：英文界面出现任何中文；或按钮显示原始 key；或校验码无障碍标签仍为中文；或中文文案与上一正式版不一致；或弹窗文字被截断。

## 用例 5：网页版授权弹窗本地化（英文必做）

1. 语言设为 **English**，`连接` → 网页版，输入邀请码，生成二维码。
2. 手机浏览器扫码，等 Mac 弹出授权弹窗。
   - 预期：标题为英文 `Allow "<设备名>" to connect to the Mobile Web Remote?`
   - 预期：说明为英文且提到 one-time session、4-digit code、not saved as a long-term trusted device
   - 预期：两个按钮为 `Allow Connection` / `Deny`，无中文
   - 预期：4 位校验码与手机页面一致
3. 点 `Deny` 与 `Allow Connection` 各走一次。
4. 语言切回中文重复一次，文案应与上一正式版逐字一致。

失败判定：同用例 4。

## 用例 6：字号改动未影响任何交互

1. 按键映射页：点击任一按键卡片的单击/双击/长按格子，确认动作编辑面板正常展开并可保存。
2. 录制一个自定义快捷键，确认成功提示（12pt 语义）正常显示。
3. 连接页：切换语音键模拟 Fn 开关、选择麦克风、发送测试音。
4. 统计页：切换今日/本周/总计，确认图表柱顶数值标签正常显示且不重叠。
5. 关于页：切换语言、导出并导入一次配置，确认状态行文案正常。

失败判定：任一交互失效；或图表数值标签因字号变大而互相重叠、被裁切。

## 稳定功能回归项（fork 专有行为，必须逐项确认）

- **可配置语音触发键**：把语音触发键分别设为 Fn、右 Command、右 Shift、右 Option，各按住说话一次，均能正常出声、正常结束。
- **外接麦克风采集**：选择外接麦克风后按住语音键，确认音频来自外接麦而非遥控器。
- **右侧修饰键不粘滞**：使用右 Command / 右 Shift / 右 Option 作为语音键，松开后立刻在文本框输入，确认**没有**修饰键残留（不出现全选、不出现大写、不触发菜单）。
- **自定义快捷键左右保真**：用右 Command + 逗号录制一个快捷键，确认界面显示带侧别（「右⌘,」/「R⌘,」），并在第三方软件中触发成功。
- 语音链路：`STREAM_START → AUDIO → STREAM_STOP` 一次成功，不需要第二次尝试。
- 按键映射：单击 / 双击 / 长按各触发一次，动作正确。
- 遥控器断连重连后自定义映射仍生效。

失败判定：以上任一项与上一正式版行为不同。

## 验证边界

- **自动化已覆盖（`swift test` 336 项 / 29 suite、`./scripts/test.sh` 42 项、边界检查均通过）**：
  - 六个字号 token 的磅值与字重真实值，全部 ≥ 12pt；统计数值缩放到底仍 ≥ 12pt 的乘积
  - 提示条内每个字体都必须是 token 或 ≥ 12pt 显式字号，且两类数量之和等于字体总数
  - 两个授权弹窗实际请求的 9 个 key 在两份 `.strings` 中都能解析出非空值、占位符数量与传参一致、英文值不含 CJK 字符
  - `cardToRemoteClearance` 在 600–2000pt 窗口逐 1pt 扫描下恒 ≥ 29pt；生产宽度下卡片宽仍为 300pt
- **代理完全未做、必须由人工在真实窗口上看**：
  - 本手册**全部用例**。自动化只能证明数值与 key 正确，**不能证明任何一处没有被裁切、没有重叠、观感可读**。
  - 字号从 10pt 抬到 12pt、11pt 抬到 13pt 会让文字变宽变高，**固定高度容器存在裁切风险**（映射页卡片高度硬编码为 72pt），用例 1 第 4 步是本次最需要人看的一项。
  - 英文授权弹窗文案比中文长，实际弹窗宽度与换行未验证。
  - 用例 3B 依赖截图渲染工具，其结果不等于真实可交互窗口。
- **门禁措辞已解决**：`AGENTS.md:64` 原要求在 `800 × 650` 窗口逐一点击侧边栏，但生产 `minSize` 为 `1020 × 772`，该尺寸不可达、门禁按字面无法执行。该门禁已改为**跟随当前生产 `minSize`**（`a7b5c4d`），`minSize` 本身未改；更窄布局改用离屏渲染（`REMOTE_MIC_SETTINGS_SCREENSHOT_SIZE`）检查并注明为离屏结果。背景与结论见 [`Bugs/2026-08-21-interface-breaks-the-projects-own-font-and-locale-rules.md`](../Bugs/2026-08-21-interface-breaks-the-projects-own-font-and-locale-rules.md) 的 A9-4 一节。用例 3A 用生产最小窗口，用例 3B 用截图工具（离屏），二者共同满足门禁。

## 自动渲染门禁能证明什么、不能证明什么

`Tests/RemoteMicTests/SettingsPageRenderingTests.swift` 会用仓库自带的离屏渲染器把 5 个设置页在
`1020 × 772` 与 `800 × 650`、中英双语、浅色与深色下各渲染一遍。

**能证明**：页面不崩、数量为 5、渲染结果没有改变请求的窗口几何（对应 `AGENTS.md`「不得改变窗口几何」）、
映射页确实画出了遥控器图（即卡片没有把它整块盖掉）。

**不能证明字号与文案**：约一半界面字符串走 SwiftUI 的 `Text("some.key")`，它按**主 bundle** 查表。
在 `swift test` 进程里主 bundle 是测试宿主，不含 `.lproj`，所以这些字符串会渲染成原始键名
（例如 `statistics.voice_ranking.title`）。**这是测试环境现象，不是 App 缺陷**——App 里
`SettingsView` 设置了 `.environment(\.locale, localization.locale)`，且 App bundle 带完整资源表。

因此本手册第 1–5 项的目视检查**不能**用自动渲染代替，仍必须由人在真实窗口里逐页确认。想拿到
文案正确的截图，只能用 App 二进制配合 `REMOTE_MIC_SETTINGS_SCREENSHOT_DIR`，且需要一个真实的
图形会话（无会话时进程会被 SIGKILL）。
