# 设置读不出来时的提示与可恢复性测试

## 适用版本或分支

- 分支：包含 `Bugs/2026-08-21-settings-decode-failure-silently-resets-configuration.md` 修复的分支
- 平台：macOS 14 及以上（Intel 变体为 macOS 13 及以上）
- 设备：不需要遥控器即可完成用例 1–5；用例 6 需要 RC003 或 RC001 做稳定回归
- 语言：中英各跑一遍

修复前的行为：任何一项设置解码失败都会被静默当成"首次使用、还没有数据"，直接换回默认值，日志里没有任何记录，界面上也没有提示。用户看到的是"配置自己丢了"。修复后解码失败会保留原始字节、写一行日志，并在按键映射页顶部显示内联提示。

**本手册测试的是防御性加固。** 目前没有证据表明已有用户真的命中过解码失败；此前那次配置丢失的根因是 HID 就绪时机（见 `Bugs/2026-08-21-remote-reconnect-loses-custom-button-mapping.md`）和安装器重定位，不是本项。因此这里的用例需要人为制造损坏数据。

## 测试前准备

1. 安装被测版本并至少启动一次，确认 App 能正常读写设置。
2. 先做一份配置导出（设置 → 导入导出），用来在测试结束后恢复现场。
3. 在按键映射页设置至少两个可识别的自定义动作（例如菜单键单击 = `Command + S`，主页键单击 = 打开某个自定义 APP），确认它们生效。
4. 准备读写 `UserDefaults` 的方式：`defaults` 命令行工具即可。Bundle ID 为 `com.hd838a.RemoteMic`。
5. 打开 `~/Library/Logs/RemoteMic/runtime.log`，记录每个用例的本地开始与结束时间。

## 用例 1：基线——正常读写不得出现任何提示

1. 正常启动 App，进入按键映射页。
   - 预期：页面顶部**没有**任何"读不出来"提示；自定义动作全部保留并可执行。
2. 退出 App 再启动一次。
   - 预期：同上，配置稳定，日志中没有 `SETTINGS decode_failed`。

失败判定：全新或正常的配置触发了提示；或日志出现 `SETTINGS decode_failed` 却没有任何损坏数据。

## 用例 2：制造一项损坏——按键映射

1. 完全退出 App。
2. 把按键映射对应的键值写成一段不可解码的数据（例如写入一个字符串而不是原本的 JSON）。用 `defaults read com.hd838a.RemoteMic` 先确认键名，再用 `defaults write` 覆盖。
3. 启动 App，进入按键映射页。
   - 预期：页面顶部出现内联提示，标题为「部分设置读不出来，已经暂时换回默认设置」，并在受影响项里点名「遥控器按键映射」。
   - 预期：提示同时说明原内容没有被删掉，以及重新设置一次即可继续使用。
   - 预期：提示是页面内的一块内容，**不是** Sheet、Popover 或需要点掉的弹窗。
4. 检查日志。
   - 预期：出现一行 `SETTINGS decode_failed key=<键名> bytes=<字节数> error=<解码错误>`，键名与实际损坏的键一致。
5. 检查 `UserDefaults`。
   - 预期：存在 `<键名>.corrupt`，内容与你写入的损坏字节一致——原始数据被保留而不是被覆盖。

失败判定：界面没有提示；提示没有点名具体项；日志没有记录或键名不对；`.corrupt` 备份不存在或内容不是原始字节；提示以弹窗形式出现。

## 用例 3：重新设置后提示自动消失

1. 在用例 2 的状态下，重新设置被清空的那几个按键动作。
2. 观察页面。
   - 预期：设置完成后提示自动消失，不需要重启 App，也没有"我知道了"之类的手动关闭按钮。
3. 退出并重新启动 App。
   - 预期：提示不再出现；新设置的动作正常执行。

失败判定：重新设置后提示仍在；或必须重启 App 才消失；或提示消失了但新设置没有保存。

## 用例 4：多项同时损坏

1. 完全退出 App，同时损坏两项以上不同的设置键。
2. 启动 App。
   - 预期：提示把受影响的项**全部列出**，之间用「、」分隔，不是只显示第一项，也不是显示原始键名。
   - 预期：日志中每一项各有一行 `SETTINGS decode_failed`。

失败判定：只列出一项；把内部键名直接显示给用户；或多项只写了一行日志。

## 用例 5：英文界面

1. 把系统语言或 App 语言切到英文，重复用例 2。
   - 预期：提示全文为英文，没有中文残留，没有显示原始本地化键名（例如 `settings.corrupted.title` 这样的字符串直接上屏即为失败）。
2. 检查字号。
   - 预期：提示正文与受影响项文字均不小于 12pt（本仓硬性约束，见 `AGENTS.md`）。

失败判定：中英混排；键名上屏；字号小于 12pt。

## 用例 6：稳定功能回归（fork 专有行为，必须逐项确认）

在存在提示和已清除提示两种状态下各确认一次：

- 语音键触发键可配置：Fn / 右 Command / 右 Option / 右 Shift 四种设置各自仍能触发。
- 外接麦克风采集：关闭"用遥控器自带麦克风收音"后，外接麦路径仍正常。
- 右侧修饰键不粘滞：按住再松开右侧修饰键，不遗留按下状态。
- 自定义快捷键左右侧保真：录入右 Command 组合后，执行时按下的仍是右侧那一枚。

失败判定：任一项在提示出现期间或消失之后行为与上一正式版不一致。

## 日志收集

出现问题时提供：

1. `~/Library/Logs/RemoteMic/runtime.log`（如已轮转，附上 `runtime.log.1` 等）。
2. `defaults read com.hd838a.RemoteMic` 的完整输出，以及你写入的损坏数据本体。
3. 复现时的本地时间、系统语言、App 版本与 Build。
4. 提示区域的截图。

## 验证边界

- 自动化覆盖：`Tests/RemoteMicTests/SettingsCorruptionRecoveryTests.swift` 覆盖按键映射、自定义应用配置、遥控器设备配置三类解码失败都被上报，多项损坏在一次加载中各报一次，**首次运行无数据不得被当成损坏**，以及正常数据重新加载不得触发提示。`CorruptedSettingsNotice` 的受影响项映射与摘要拼接另有测试。
- **自动化不覆盖，只能由本手册人工确认**：提示是否真的渲染在按键映射页顶部、实际字号、中英文实际显示效果、以及重新设置后提示消失的时机。
- 本项修复**没有做过任何真机或界面验收**；截至撰写时，提示区域从未在真实窗口中被看到过。不得据此表述为已验收。
